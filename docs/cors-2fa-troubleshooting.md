# CORS error when enabling 2FA

The browser's missing `Access-Control-Allow-Origin` message alone does not identify
the root cause. Check both OPTIONS and POST in the Network tab.

Read-only production checks on 2026-10-04:

- OPTIONS `/api/Users/request-enable-2fa` with origin `https://docshare.id.vn`,
  requested method POST, and requested headers `authorization,content-type`
  returned 204 with the expected allow-origin, allow-methods, and allow-headers.
- POST without credentials returned 401 with the expected allow-origin header.

This confirms the deployed policy accepts this origin for those requests. It does
not verify the authenticated request or email delivery.

`RequestEnableTwoFactor` performs database writes and sends email through Resend.
Those operations can throw. Production now uses an exception handler inside the
CORS middleware, returning a generic 500 Problem Details response and logging the
exception. This makes application failures readable by an allowed browser origin;
it does not fix the underlying database or email error.

After deploying, reproduce with a signed-in account and inspect API logs at the
request time. For an email failure, verify `RESEND_API_KEY`, `RESEND_FROM_EMAIL`,
`TWO_FACTOR_EMAIL_TEMPLATE_ID`, and `DOMAIN`, and inspect the provider error. Check
database connectivity if the stack trace points to an EF Core operation.

If email arrives but saving the challenge fails, inspect the inner exception and
the `TOKENS.user_device` column. The legacy schema used `varchar(45)`, which is too
short for the persisted challenge JSON. Run `docs/two-factor-challenge-migration.sql`
against the affected database to widen it to TEXT. The EF mapping alone does not
alter an existing database. Initial 2FA flows now save challenge state before
sending email, so a persistence failure cannot send an unusable code.

If OPTIONS fails, verify `CORS_ALLOWED_ORIGINS` includes exactly
`https://docshare.id.vn` (no path or trailing slash). If POST returns a gateway
error such as 502/504, check Render/Cloudflare and upstream availability; the
application cannot add headers to a response generated by a proxy.
